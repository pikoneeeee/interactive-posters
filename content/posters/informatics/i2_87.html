Іске асыру — бұл не? What is implementation? Что такое реализация?

Іске асыру (implementation) — алгоритмді белгілі бір тілде (Python, C++, JavaScript) кодтай бастау. Бірақ кодты жазу — жобаның тек 30%-ы! Қалғаны — тестілеу (30%) және жөндеу/оптимизация (40%). Тестілеу — кодтың шынымен дұрыс жұмыс істейтінін тексеру. Microsoft Office-де кез келген функция 1 000+ тестпен тексеріледі. NASA-ның бағдарламаларында — 10 000+! Implementation means coding the algorithm in a real language (Python, C++, JS). Writing code is only 30% of the project! The rest is testing (30%) and debugging/optimisation (40%). Testing proves that the code really works. MS Office features run through 1 000+ tests. NASA software — 10 000+! Реализация — кодирование алгоритма на конкретном языке (Python, C++, JS). Но написание кода — лишь 30% проекта! Остальное — тестирование (30%) и отладка/оптимизация (40%). Тестирование проверяет, что код работает правильно. Функция в MS Office проходит 1 000+ тестов. В NASA — 10 000+!

def is_prime(n): if n < 2: return False for d in range(2, int(n**0.5) + 1): if n % d == 0: return False return True # тесттерtestsтесты assert is_prime(2) == True assert is_prime(7) == True assert is_prime(12) == False assert is_prime(1) == False # edge assert is_prime(97) == True print("✅ All tests passed!")

🤖 Автоматты тесттер — pytest 🤖 Automated tests — pytest 🤖 Автотесты — pytest

Python-ның стандартты кітапханасы — unittest, ең танымал сыртқысы — pytest. Әр коммитте автоматты тексеру — «CI/CD» деп аталады. Python's built-in library is unittest; the most popular external one is pytest. Running tests on every commit is called «CI/CD». Встроенная библиотека — unittest, самая популярная сторонняя — pytest. Автоматический прогон тестов на каждом коммите называют «CI/CD».

# test_math.py from mymath import add def test_add_positive(): assert add(2, 3) == 5 def test_add_zero(): assert add(0, 0) == 0 def test_add_negative(): assert add(-2, 3) == 1 # терминалда:in terminal:в терминале: # $ pytest → ✅ 3 passed

📜 TDD — «тест алдымен» 📜 TDD — test-driven development 📜 TDD — «сначала тест»

Керемет әдіс: 1) тестті жаз, ол ❌ қызыл болады (әлі код жоқ). 2) кодты жаз — тест ✅ жасыл. 3) тазала. Кент Бек ойлап тапқан (1999) — бүгінде Google, Microsoft, Яндекс пайдаланады. A powerful approach: 1) write failing test (❌ red). 2) write code to pass (✅ green). 3) refactor. Invented by Kent Beck (1999) — used by Google, Microsoft, Apple. Методика: 1) пишем падающий тест (❌ красный). 2) пишем код — тест ✅ зелёный. 3) чистим. Создал Кент Бек (1999) — применяют Google, Microsoft, Яндекс.
