Контейнеры и Docker

📦 Контейнер — не? 📦 What is a container? 📦 Что такое контейнер?

Контейнер — қосымша мен оның барлық тәуелділіктерін (кітапханалар, конфиги, орта айнымалылары) бір «қорапқа» орайтын тәсіл. Әдетте әзірлеуші машинасында «менде жұмыс істейді!» — ал серверде іске қосылмайды. Контейнер бұл мәселені шешеді: бір рет жинайсың — бәрі жерде бірдей жұмыс істейді. Тарих: Linux cgroups + namespaces (2008) → Docker 2013 (Solomon Hykes) → Kubernetes 2014 (Google). Бүгін кез келген ірі сайт контейнерлерде жұмыс істейді. A container packages an app with all its dependencies (libraries, configs, env-vars) into one box. The classic «works on my machine» problem disappears: build once, run anywhere. History: Linux cgroups + namespaces (2008) → Docker 2013 (Solomon Hykes) → Kubernetes 2014 (Google). Today virtually every major service runs in containers. Контейнер — способ упаковать приложение вместе со всеми зависимостями (библиотеки, конфиги, переменные среды) в одну «коробку». Классическая проблема «у меня работает!» исчезает: собрал один раз — работает везде. История: Linux cgroups + namespaces (2008) → Docker 2013 (Соломон Хайкс) → Kubernetes 2014 (Google). Сегодня почти любой большой сервис работает в контейнерах.

🎼 Kubernetes — оркестр 🎼 Kubernetes — orchestration 🎼 Kubernetes — оркестрация

Бір контейнер — оңай. Ал 1000 контейнерді басқару қиын: қайсысы қай серверде, қайсысы құлады, трафик қалай бөлу. Бұл мәселені Kubernetes (K8s) шешеді — «контейнерлердің дирижёры». Google 2014 ж. ашты. One container is easy. Managing 1000 containers — not so much: which runs where, which crashed, how to load-balance. Kubernetes (K8s) solves this — «container conductor», open-sourced by Google in 2014. Один контейнер — легко. Управлять 1000 контейнерами — ад: какой где, какой упал, как балансировать трафик. Эту задачу решает Kubernetes (K8s) — «дирижёр контейнеров», открыт Google в 2014 г.
