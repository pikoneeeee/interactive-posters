Реляционные БД: поля, записи, индексы

🗃 Реляциялық — не? 🗃 What is «relational»? 🗃 Что такое «реляционная»?

Реляциялық дерекқор (РБД) — деректерді кестелерде (relations) сақтайтын жүйе. Идеяны 1970 ж. Edgar Codd IBM-да ұсынды. Кесте — жолдардан (жазба, record) және бағандардан (өріс, field) тұрады. Кестелер бір-бірімен кілттер арқылы байланысады. Ең танымалы: MySQL, PostgreSQL, SQLite, Oracle, SQL Server. Барлық банктер, билеттер, мектеп журналы — осында. A relational database (RDB) stores data in tables (relations). The idea was introduced by Edgar Codd (IBM, 1970). A table has rows (records) and columns (fields). Tables connect via keys. Popular engines: MySQL, PostgreSQL, SQLite, Oracle, SQL Server. Banks, ticket systems, school registers — all relational. Реляционная БД (РБД) хранит данные в таблицах (отношениях). Идею предложил Эдгар Кодд (IBM, 1970). Таблица состоит из строк (записей) и столбцов (полей). Таблицы связаны через ключи. Популярные: MySQL, PostgreSQL, SQLite, Oracle, SQL Server. Банки, билеты, школьный журнал — всё здесь.

⚡ Индекс — бас дерек ⚡ Index — secret weapon ⚡ Индекс — секретное оружие

Индекс — кітаптың алфавиттік тізімі сияқты: «қай жолда қандай мән жатыр». Ол жоқ болса — сервер барлық 1 млн жолды қарап шығады (full scan). Индекс бар болса — B-tree арқылы 20 адымда табады. Жеделдік 50 000×-ке дейін өседі! An index is like a book's alphabetical guide: «which row has which value». Without it the server scans all 1 M rows (full scan). With a B-tree index only ~20 steps are needed. Up to 50 000× faster! Индекс — как алфавитный указатель в книге: «на какой строке какое значение». Без него сервер просматривает все 1 млн строк (full scan). С индексом (B-tree) — всего ~20 шагов. Ускорение до 50 000×!

-- создать индекс CREATE INDEX idx_city ON students(city); -- теперь этот запрос летает: SELECT * FROM students WHERE city = 'Almaty';
