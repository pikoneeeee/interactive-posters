Primary and foreign key

Первичный и внешний ключ

🔑 Кілт — не үшін? 🔑 Why keys? 🔑 Зачем ключи?

Бір кестеде 10 «Айгүл» болуы мүмкін — қайсысы туралы айтып тұрмыз? Кілттер — жолды бір мәнде табатын өріс(тер). Primary Key (PK) — осы кестенің «паспорты». Foreign Key (FK) — басқа кестемен байланыс: «менің сыныбымның идентификаторы — 25-ші жол». Кілттер тұтастықты (integrity) қамтамасыз етеді: «жоқ оқушыға бағаны қоюға болмайды». One table may have 10 «Aigul» — which one do we mean? Keys uniquely identify a row. A Primary Key (PK) is the table's «passport». A Foreign Key (FK) is a link to another table: «my class_id is row 25». Keys enforce data integrity: you can't grade a student who doesn't exist. В таблице может быть 10 «Айгуль» — о какой речь? Ключи однозначно идентифицируют строку. Первичный ключ (PK) — «паспорт» этой таблицы. Внешний ключ (FK) — связь с другой таблицей: «мой class_id ссылается на 25-ю строку». Ключи обеспечивают целостность: нельзя поставить оценку несуществующему ученику.

Табиғи кілт: ИИН, ISBN, e-mail. Синтетикалық: id INTEGER AUTOINCREMENT — қарапайым, сенімді. Natural key: SSN, ISBN, email. Surrogate: id INTEGER AUTOINCREMENT — simple and reliable. Естественный ключ: ИИН, ISBN, e-mail. Суррогатный: id INTEGER AUTOINCREMENT — просто и надёжно.

CREATE TABLE students ( id INTEGER PRIMARY KEY AUTOINCREMENT, name VARCHAR(100) NOT NULL, iin CHAR(12) UNIQUE, class_id INTEGER ); -- составной PK (два столбца образуют уникальность) CREATE TABLE marks ( student_id INTEGER, subject_id INTEGER, mark INTEGER, PRIMARY KEY (student_id, subject_id) );

🔗 Foreign Key (FK) 🔗 Foreign Key (FK) 🔗 Внешний ключ (FK)

FK — басқа кестенің PK-сына сілтейді. «Студент 25-сыныпта» — students.class_id → classes.id. FK points to the PK of another table. «Student in class 25» — students.class_id → classes.id. FK ссылается на PK другой таблицы. «Ученик в классе 25» — students.class_id → classes.id.

CREATE TABLE classes ( id INTEGER PRIMARY KEY, name VARCHAR(10) ); CREATE TABLE students ( id INTEGER PRIMARY KEY, name VARCHAR(100), class_id INTEGER, FOREIGN KEY (class_id) REFERENCES classes(id) );

🛡 Референциалды тұтастық 🛡 Referential integrity 🛡 Ссылочная целостность

Егер «classes» кестесінен 10А сыныбын жойсақ — онда оған сілтейтін оқушылармен не болады? Жауабын ON DELETE және ON UPDATE айқындайды: If we delete class 10A from «classes», what happens to students pointing to it?
